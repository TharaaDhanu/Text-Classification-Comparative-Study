# Comparative Study of Machine Learning Algorithms for Text Classification

A reproducible NLP / Machine Learning project comparing **Decision Tree, K-Nearest Neighbours (KNN), Support Vector Machine (SVM), and Naïve Bayes** on IMDb movie-review sentiment classification.

## 1. Problem definition

Given a movie review, predict its sentiment:

- `positive`
- `negative`

This is a **binary text-classification** problem.

## 2. Dataset

Use the IMDb 50K Movie Reviews dataset from Kaggle:

<https://www.kaggle.com/datasets/lakshmi25npathi/imdb-dataset-of-50k-movie-reviews>

Expected CSV filename: `IMDB Dataset.csv`

Expected columns:

| Column | Meaning |
|---|---|
| `review` | Movie-review text |
| `sentiment` | `positive` or `negative` |

Download the CSV yourself and place it in `dataset/`. The dataset is not included in this repository because it is a third-party dataset and should be obtained from its source.

## 3. Algorithms

1. Decision Tree
2. K-Nearest Neighbours (KNN), using cosine distance and `k=5`
3. Linear Support Vector Machine (SVM), using `C=1.0`
4. Multinomial Naïve Bayes

## 4. Experimental procedure

- Remove missing rows and invalid labels.
- Select a balanced sample: 5,000 positive and 5,000 negative reviews (10,000 total).
- Clean text by lowercasing, removing HTML tags, punctuation/numbers, and extra whitespace.
- Split into 80% training and 20% testing with stratification and `random_state=42`.
- Fit TF-IDF on training text only; transform test text using the fitted vectorizer.
- Use the same split and TF-IDF features for all four algorithms.
- Evaluate Accuracy, Precision, Recall, and F1-score. Positive sentiment is the positive class for Precision, Recall, and F1-score.
- Generate a performance comparison graph and four confusion matrices.
- Conduct a what-if experiment by changing SVM `C` from `1.0` to `0.1`, keeping the dataset, split, and features unchanged.

**Why fit TF-IDF only on training data?** This avoids test-set information leaking into feature extraction and gives a fairer estimate of performance on unseen reviews.

## 6. Run using Google Colab

1. Open `Text_Classification_Comparative_Study.ipynb` in Google Colab.
2. Run the cells in order.
3. Upload `IMDB Dataset.csv` when prompted.
4. Review the generated metrics, graph, and confusion matrices.
5. Save your actual results and use them to complete `reports/report_template.md`.

## 7. Run locally

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

Place the CSV at `dataset/IMDB Dataset.csv`, then run:

```bash
python src/run_experiment.py --csv "dataset/IMDB Dataset.csv"
```

For a smaller trial run:

```bash
python src/run_experiment.py --csv "dataset/IMDB Dataset.csv" --samples-per-class 1000
```

The default experiment uses 5,000 records per class. KNN can take longer than the other models because it compares test examples with training examples.

## 8. Generated outputs

The experiment writes the following files into `results/`:

- `algorithm_comparison.csv` — four-model metric table
- `performance_comparison.png` — grouped metric bar chart
- `confusion_matrices.png` — 2×2 panel of confusion matrices
- `svm_what_if_comparison.csv` — SVM C=1.0 vs C=0.1 results
- `run_summary.txt` — short run summary
- `*_classification_report.txt` — per-model precision/recall/F1 reports

These are generated when you run the experiment. **No experimental metric values are pre-filled or fabricated.**

## 11. Limitations

- The experiment uses a balanced 10,000-review sample by default, not all 50,000 reviews.
- Results depend on the sampled records, preprocessing, TF-IDF settings, and model parameters.
- The positive class is explicitly used for Precision, Recall, and F1-score.
- The recommendation in the report must be based on your actual run, not a general claim about which algorithm is always best.
